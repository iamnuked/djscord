# 공개 전 실행 검증

검증일: 2026-10-21. 로컬 macOS 앱, Docker Compose의 봇·Lavalink,
테스트용 Discord 서버에서 확인했습니다. 서버 식별자와 인증 정보는 기록하지 않습니다.

## 확인한 동작

- 봇과 Lavalink 시작, 연결 준비, 맥 앱에서 서버 종료.
- Discord 음성 채널에 연결된 채팅에서 곡 검색·선택·재생.
  ISOxo의 MOLLY TALK 재생 소리는 사용자가 직접 확인했습니다.
- Discord의 일시정지와 맥 앱의 재개·대기열 추가·다음 곡·종료.
- 명령어 20개 등록: DJ Engine 명령어 제외, 시스템 오디오 명령어 포함.
- 데스크톱 API의 인증 누락·브라우저 Origin 거절 및 잘못된 명령 검증.
- QuickTime Player만 선택해 직접 만든 440Hz 테스트 WAV를 캡처.
  컨테이너에서 캡처 서버의 HTTP 200과 비영(非零) PCM 신호를 확인했습니다
  (최대 진폭 1600, RMS 약 1131).
- 시스템 오디오 플레이어가 `playing=true`, `paused=false`,
  `systemAudio=true`인 상태를 확인했습니다.
- 방송과 캡처를 종료하고 믹서 선택을 기존 상태로 복원했습니다.

시스템 오디오 테스트 때 사용자는 다른 음성 채널에 연결되어 있었습니다.
따라서 시스템 오디오의 Discord 수신측 청취 여부는 확인하지 않았습니다.

## 실행 중 수정한 문제

- 맥 앱의 곡 검색에 공통 검색 해석기를 적용했습니다.
  YouTube Music 검색 결과가 비어 있어도 일반 YouTube 검색으로 찾습니다.
- 오디오 미터는 변경된 값만 하나의 화면 상태로 반영하도록 수정했습니다.
  무음 상태에서 반복된 화면 갱신으로 앱이 느려지는 문제가 해소되었고,
  수정 후 관측한 CPU 사용률은 약 2%였습니다. 이는 특정 환경의 관측값입니다.

## 코드 검증

- 봇: 타입 검사·테스트 146개·린트 통과.
- 웹: 기존 공개 준비 검증에서 테스트 5개 통과.
- 맥 앱: 빌드와 믹서 검증 프로그램 통과.
  미터 갱신 생략, 피크, 무음, 채널 합산, 개별 볼륨, 리샘플링,
  버퍼 상한을 확인했습니다.

Git 커밋과 GitHub 업로드는 이 검증에 포함하지 않았습니다.
